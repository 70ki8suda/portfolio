# このブログの日本語執筆・推敲

読者が内容を理解しながら、無理なく先を読める文章を書く。情報を薄めて短くするのではなく、説明の順序、言葉、文と段落の呼吸を整える。

このスキルは humanizer-jp の編集方針をブログ向けに再構成したもの。特定の作家へのなりきりや固有の文体の再現は行わない。作家名による要望は、平易さ、落ち着き、リズム、具体性、比喩の節度という一般的な品質に置き換える。AI判定器の回避や、人間が書いたという表示を目的にしない。

## 優先するもの

1. 元の主張、根拠、条件、情報量を保つ。
2. 誰の発言・解釈なのかを明確にする。
3. 読みやすい順序と自然な日本語に整える。
4. 必要なところだけ、リズムや比喩を調整する。

美しい言い回しと正確な説明が衝突したら、説明を取る。編集対象以外の機能やデザインには作業を広げない。

## 語り口

- 基本は落ち着いた「です・ます」。読者と同じ高さから説明し、教師のように理解を促したり、感動を指示したりしない。
- 短い文は、説明を区切るために使う。条件や因果が複雑な箇所は長くてもよい。長短を機械的に交互にしない。
- 一段落に一つの話題を置く。段落の末尾を毎回、教訓・名言・問いかけで締めない。説明が終わったら、そのまま次へ進んでよい。
- 抽象語より、誰が何をするかを書く。具体的な人・物・行動は原稿や資料にあるものを使い、リアリティのための細部を創作しない。
- 比喩は仕組みの理解を助けるときに限る。比喩を外したら何も残らない文は、説明から書き直す。既存の仮定例は条件を残す。
- 一人称や感想はユーザーが述べた内容、または元原稿にある声を尊重する。架空の思い出、生活習慣、読後感、文学的な人物像を追加しない。
- 慎重な留保は残す。「予測」「仮定」「本人の見方」を、文章の勢いのために確定した事実へ変えない。

## humanizer-jpから引き継ぐ編集判断

次の傾向を文脈ごとに点検する。禁止語リストとして一括置換しない。

- 「本記事では解説します」「まず見ていきましょう」など、内容の前に置かれる進行説明。
- 「重要なのは」「本質は」「大きな一歩」など、理由のない評価や意義の水増し。
- 「単なるXではない。Yだ」の反復、無理な三点セット、すべての段落に同じ型を当てる書き方。
- 「時間の厚み」「未来への入口」など、何を指すのか説明できない抽象的な比喩。
- 「することができます」などの冗長な述語。同じ主語・語尾・接続詞の連続。
- 本文を言い換えただけの小見出しや結論、説明のあとに付く不要な褒め言葉。
- 短い断定や体言止めを連打する広告調のリズム。

正確な専門用語、機能的な表や箇条書き、主張と補足を分ける見出しは残す。文法の一貫性や特定の句読点だけを理由に直さない。原典のダッシュ禁止などは機械的に適用せず、引用・作品名・リンク・メタデータを守る。

## 既存記事の推敲

- 対象記事を全文読み、章ごとの主張、具体例、数値、留保、出典を把握する。長文は分割して読み、冒頭だけを見て全体を置換しない。
- 下書き、内容照合、文章の読み直しを内部で行い、ファイルには最終稿だけを残す。
- 論点・事例・数値の条件を削って要約版にしない。同じ情報の繰り返しや進行説明は整理してよい。文字数そのものを品質目標にしない。
- 動画の主張、筆者の考察、仮定の数値例を混ぜない。前置きを省くなら、見出しや近くの文で区別が残ることを確かめる。
- frontmatter、URL、明示アンカー、YouTubeのコードフェンス、表の数値は維持する。変更が必要なら、依頼の対象かを確認し、目次や参照箇所も一緒に扱う。
- Garys Economicsの統合記事では、14本分の説明・例・注意点を保つ。時事動画は収録時点の認識や予測として扱う。
- ソーラーパンク記事では、3人の一致点と意見の違いを残す。サイトの水耕栽培の風景についての筆者の考察を、動画の発言や実証済みの性能と混同しない。

## 新規記事の執筆

- 指定資料を確認してから構成する。資料を取得できない箇所は、確認できたかのように補わない。
- 冒頭は、記事で説明する具体的な疑問や状況から入る。読後の効用を約束する宣伝文を置かない。
- 節の数や構造は内容に合わせる。「定義・メリット・課題・未来」などの型を先に押し付けない。
- 新しい具体例を作る場合は仮定であることを示し、実際の出来事や話者の例として紹介しない。
- 出典と動画埋め込みは既存記事のMarkdown形式に合わせる。全文翻訳や逐語的な再構成ではなく、論点を自分の構成で説明する。

## 編集例

以下は本スキル独自の例。特定の作家の文章を模したものではない。

**進行説明を内容に替える**

前：ここからは、お金と実物資源の違いについて詳しく見ていきましょう。

後：お金を配っても、会場の座席は増えません。

この書き換えは、前後ですでに席数が固定された会場の例を置いている場合に使える。資料にない設定を勝手に足さない。

**比喩より作業を書く**

前：手入れの時間の厚みが、未来の風景に命を吹き込みます。

後：植物は育ちます。水やりや剪定も続きます。その作業を誰が担うかは、完成予想図からは分かりません。

**慎重さを削らない**

前：Garyの予測は、格差の拡大が経済を必ず崩壊させることを示しています。

後：Garyは、格差が広がれば生活水準は下がり続けると予測します。この動画だけで、その予測が正しいとは確かめられません。

## 最終確認

元原稿と差分を照合し、論点や条件の欠落、話者の取り違え、新しい事実の混入がないかを確認する。次に文章として通読し、説明の重複、不自然な文の切れ目、装飾のための比喩を直す。

記事を更新した場合は、目次のリンク先、動画、表、表示を変更リスクに応じて確認する。確認できた範囲と変更点を短く報告する。依頼がスキル作成だけなら、既存記事の再編集は行わない。

## 執筆・改稿後のグラフ分類

記事を新規作成したときや本文を変えたときは、執筆を完了する前に[段落グラフの運用手順](../../../docs/content/paragraph-graph.md)を読み、編集メタデータと生成物も更新する。通常一覧への公開可否は `draft`、長く育てるテーマの地図への適格性は編集分類で別々に判断する。分類だけを理由に公開・非公開を変更しない。

`npm run graph:classify-input -- /tmp/graph-editorial-input.json` でローカルに出した本文・`sourceHash`・既存判断・人の override・変更状況を確認する。対象記事を全文読み、本文の主目的から次を選ぶ。日付、slug、単語やテーマタグの一致で代用しない。

| category | 本文の主目的 | 通常の decision |
| --- | --- | --- |
| `long-term` | 所有、暮らし、思想、技術と社会など、後から問い直せる概念を論じる | 概念を論じる段落があれば `include` |
| `current-affairs` | 特定時点の出来事、企業、相場や数値を調べ、現状を判断する | `exclude` |
| `curation` | 音楽・動画・作品などの選曲や紹介を届ける | `exclude` |
| `other` | 上記以外が主目的で、段落をまたぐ概念探究には向かない | `exclude` |
| `uncertain` | 主目的やグラフへの適合を判断しきれない | `review` |

時事の例が含まれていても、主目的が持続的な概念の探究なら `long-term` にできる。逆に、AIや所有という語を含むだけの企業調査は対象にしない。選曲にまとまった概念論が加わった場合も、曲名ではなく記事全体の主目的を読み直す。分類と適格性が食い違う、または根拠が弱い場合は理由を記して `review` とし、グラフに入れず確認を待つ。

判断は `content/graph-editorial.json` の対象 slug に、入力から得た `sourceHash`、`category`、`decision`、本文のどこを根拠にしたかが分かる `reason`、`decidedBy: "ai"` を記録する。人が指定した `override` は優先し、AIの再分類で削除・上書きしない。本文が変わっても override は保持し、`sourceHash` とAI側の分類・理由を更新する。既存判断と本文が変わっていない記事は、今回の編集に便乗して分類を変えない。

運用手順に従い、今回の対象記事に範囲を絞って `npm run graph:sync-optin` で有効な判断を frontmatter の `graph` に同期する。`review` は人の明示 override がない限り `graph: false`。`include` でも `draft: true` の記事はグラフ生成物に含めない。

グラフ参加記事の本文変更後は、段落を再抽出し、旧IDと新IDを照合する。追加・変更された段落を読んでタグと話者・留保を付け直し、削除・参加解除された段落の古いタグを除く。変更のない本文のembeddingは再利用できるが、変更・削除された本文のベクトルは失効させる。`graph:build`、`graph:check` と運用手順の対象テストで、本文・分類・タグ・ベクトル・公開JSONの一致を確認してから執筆完了とする。機械の検査は判断の鮮度と整合性を確かめるもので、AIの読解や関連候補の内容監査を代わりに行うものではない。
