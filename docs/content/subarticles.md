# サブ記事

`parentArticle: <公開済み親記事のslug>` をfrontmatterに指定する。サブ記事も `draft: false` で通常の `/blog/<slug>` から公開され、SSR・原文anchor・コメントを使える。`draft` やカテゴリー、話題タグ、graph適格性とは別の分類である。

一覧APIは `listedPosts` を共通投影として使い、サブ記事を通常一覧、カテゴリー/タグ絞込み、タグ選択肢、件数から除く。直接記事取得・sourceHash・graph corpusからは除かない。検索エンジンへの非公開を意味しない。

全記事読込時に親不存在・自己参照・循環・draft親・slug重複を拒否する。下書きの子も公開済み親を指定する。公開親の記事末尾には公開子へのリンク、子には元記事へ戻るリンクを出す。draft子は親の導線に出さない。本文からの自然な案内は主筆が提案し、公開時にリンク先の公開を確認する。

## 追加・改稿

1. 主筆稿と非公開資料台帳を原典監査し、本文と親記事への案内文を固定する。
2. `parentArticle` を設定し、通常の記事日付・全文分類・索引鮮度・主要主張graph増分更新を行う。非掲載だけを理由にgraphから除外しない。親本文に案内を追加した場合も通常依存更新を行う。
3. 対象unit/型検査、SSR直接アクセス、親子往復、一覧/タグ/カテゴリーの非掲載と件数を確認する。子の公開状態を変える場合は親の導線も確認する。
4. 独立監査・readiness・clean公開後、PC/mobileで同じ導線とsource/graph整合を確認する。

検証fixtureは `BLOG_FIXTURES=1` の開発環境だけに入り、本番へ公開しない。サブ記事の機能と本文公開の証拠は分けて記録する。
